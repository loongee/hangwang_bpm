# 汉王大健康 2.2.22 通信协议

来源：`汉王大健康_2.2.22.apk`  
包名：`com.android.hanvonhealthproject`  
范围：云端 HTTP（读取远程血压数据所需）以及蓝牙测量包上传到云端的格式。设备侧 BLE 广播与特征值读写不在本文展开。

本文由客户端反编译还原，字段名与客户端 Gson 模型一致。服务端若对空字段、枚举做了额外校验，以实机响应为准。

## 1. 服务地址

| 用途 | Base URL | 切换条件 |
| --- | --- | --- |
| 血压、账号、设备 | `https://bpm.hanvon.com/` | `MyApp.urlType` 为空（默认） |
| 天地网关（问答、反馈） | `https://tiandi.hanvon.com/gateway/` | `MyApp.setUrlType` 传入非空字符串 |
| 问答 WebSocket | `wss://tiandi.hanvon.com/websocket` | 独立连接 |
| 语音识别 | `api-tiandi.hanvon.com:10095` | WebSocket，与血压接口无关 |

血压相关路径都挂在 `https://bpm.hanvon.com/` 下，前缀为 `bpmeterapp/` 或 `bpmeterbluetooth/`。

静态页：

- 隐私协议：`https://bpm.hanvon.com/bpmeter/static/agreement/privacy.htm`
- 服务协议：`https://bpm.hanvon.com/bpmeter/static/agreement/service.htm`
- 知情同意：`https://bpm.hanvon.com/bpmeter/static/agreement/consents.html`

## 2. 通用约定

- 方法：除天地网关少数接口外，全部为 `POST`。
- `Content-Type`：`application/json`（客户端使用 Spring `FastJsonJsonView.DEFAULT_CONTENT_TYPE`）。
- 序列化：Gson 默认策略。JSON 键等于 Java 字段名（驼峰）。值为 `null` 的字段不会输出。
- 超时：连接 120 秒，读/写 60 秒。
- 客户端 OkHttp **没有**挂上 `HeaderInterceptor`。因此请求里不会带 `appKey` / `randNumber` / `timestamp` / `signature`。血压接口不要自行添加这组头。

### 2.1 鉴权

登录成功后，后续接口在 HTTP 头携带：

```http
token: <登录返回的 token>
```

头名就是小写 `token`，不是 `Authorization`。

本地存储键：`token`（字符串）、`loginInfo`（`UserInfoBean` 的 JSON）。

### 2.2 统一响应

```json
{
  "code": 10001,
  "msg": "success",
  "data": {}
}
```

| code | 含义 |
| --- | --- |
| `10001` | 成功 |
| `0` | 成功 |
| `10002` | 成功，无动态数据 |
| `401` | token 失效 |
| `10070` | 不弹出自动刷新提示 |

`data` 的类型随接口变化，见下文。失败时客户端把 `msg` 当作错误文案。

## 3. 登录

`platform` 固定为 `"2"`（Android）。`isJoinRenmin`：勾选北大人民计划为 `"1"`，否则 `"0"`。

### 3.1 发送验证码

`POST /bpmeterapp/api/member/get/verify/code/new`  
无需 token。

```json
{ "username": "13800138000" }
```

`data`：字符串。

### 3.2 验证码登录（当前主流程）

`POST /bpmeterapp/api/member/verify/code/new/login`  
无需 token。

```json
{
  "username": "13800138000",
  "verifyCode": "123456",
  "platform": "2",
  "appType": "",
  "isJoinRenmin": "0"
}
```

`data`：`UserInfoBean`，其中 `token` 为后续请求凭证。

### 3.3 密码登录

`POST /bpmeterapp/api/member/account/pwd/login`  
无需 token。

密码不是明文。客户端对密码原文做 **SM3**，再把十六进制摘要转成 **大写** 放入 `password`。

```json
{
  "username": "13800138000",
  "password": "<SM3(密码).toUpperCase()>",
  "platform": "2",
  "appType": "1101091290",
  "isJoinRenmin": "0"
}
```

`data`：`UserInfoBean`。

### 3.7 当前用户

## 4. 读取血压的调用顺序

远程查看数据不需要连血压计，按下面顺序即可。

1. 登录，保存 `data.token`。
2. `POST /bpmeterapp/api/device/bind/list`，拿到 `devSn`、`devType`、`macAddr`。
3. `POST /bpmeterapp/api/measurer/list`，拿到测量人。`devMeasurer` 使用 `"1"` 或 `"2"`。
4. `POST /bpmeterapp/api/v3/device/latest/data/list`，拿每个测量人最近一条。
5. 按需拉列表、详情、趋势、统计。

公共筛选字段：

| 字段 | 取值 |
| --- | --- |
| `devSn` | 设备序列号。注意分享上传对象里写成 `devSN` |
| `devMeasurer` | `"1"` 测量人一，`"2"` 测量人二 |
| `dimension` | `hour` / `day` / `week` / `month` |
| `pageSize` | 列表固定 `50` |
| 时间 | 日、周边界为 `yyyy-MM-dd`；小时为 `yyyy-MM-dd HH:mm:ss`；月起始在界面上拼成 `yyyy-MM/01` |

### 4.1 已绑定设备

`POST /bpmeterapp/api/device/bind/list`  
Header：`token`。

`data`：`DeviceListBean[]`

| 字段 | 说明 |
| --- | --- |
| `devSn` | 序列号 |
| `devName` | 名称 |
| `devType` | 设备类型，整数 |
| `macAddr` | 蓝牙地址 |
| `imgUrl` `bgUrl` | 图片 |

绑定：`POST /bpmeterapp/api/v3/device/binding`

```json

  "devSn": "",
  "devName": "",
  "macAddr": "",
  "netMode": ""
}
```

解绑：`POST /bpmeterapp/api/device/unbind`  
改名：`POST /bpmeterapp/api/device/edit/name`

### 4.2 测量人

`POST /bpmeterapp/api/measurer/list`  
`data`：`MeasureUserInfoBean[]`

关键字段：`id`、`memberId`、`devMeasurer`、`devSN`、`nickname`、`sex`、`birthday`、`age`、`height`、`weight`、`ttrHigh`、`ttrLow`、`medicalHistoryDesc`、`useMedicineDesc`、`avatarUrl`、`genderImgUrl`。

单个测量人：`POST /bpmeterapp/api/measurer/info`  
更新资料：`POST /bpmeterapp/api/measurer/edit/info`（`PostMeasureUserInfoBean`，主键字段名是 `measurerId`）  
更新 TTR 目标：`POST /bpmeterapp/api/measurer/targetTTRValue`

```json
{
  "devSn": "",
  "measurer": "1",
  "measurerId": "",
  "ttrHigh": "",
  "ttrLow": ""
}
```

### 4.3 最近一条

`POST /bpmeterapp/api/v3/device/latest/data/list`

```json

```

`netMode` 可选。`data`：`DeviceDataListBean[]`，每个测量人一条。

### 4.4 历史列表

`POST /bpmeterapp/api/device/data/list`

```json
{
  "devSn": "",
  "devMeasurer": "1",
  "dimension": "day",
  "measuredTime": "2026-10-11 08:30:00",
  "pageSize": 50,

```

| 值 | 客户端用法 |
| --- | --- |

| `"3"` | 日历选中，或还没有选中时间 |

分组字段：`year`、`month`、`day`、`isRelpay`、`list`。

`list[]`（单次测量）：

| `originalMeasuredTime` | 校正前时间 |
| `uploadTime` | 上传时间 |
| `highVal` `lowVal` `heartRate` | 收缩压、舒张压、脉搏 |
| `bpVal` `ppdVal` | 血压展示值、脉压差 |
| `status` | 分级整数 |
| `measuredStatus` `measuredType` `measuredErrorFlag` | 状态与测量方式 |
| `measuredTimeErrFlag` | 时间是否异常 |
| `isInvalid` | 是否标记无效 |
| `source` | 数据来源 |
| `measurer` | 测量人 |
| `ifArrhythmia` `ifBradycardia` `ifTachycardia` `atrialFibrillationFlag` | 心律 |

### 4.6 趋势

`POST /bpmeterapp/api/device/trend/datas`  
请求体 `PostBloodLineBean`：

```json
{
  "devSn": "",
  "devMeasurer": "1",
  "dimension": "day",
  "beginDate": "2026-09-12",
  "endDate": "2026-10-11",
  "isDefault": ""
}
```

`data`：`BloodLineBean[]`

| 字段 | 说明 |
| --- | --- |
| `measuredTime` `highVal` `lowVal` `heartRate` | 汇总点 |
| `rowKey` `source` | 定位与来源 |
| `trendDataList` | 该点下的明细 |

`trendDataList[]`：`measuredTime`、`highVal`、`lowVal`、`heartRate`、`measuredCount`、`measuredStatus`、`status`、`rowKey`、`source`。

小时趋势：`POST /bpmeterapp/api/device/hour/trend/datas`

```json
{
  "devSn": "",
  "devMeasurer": "1",
  "beginDate": "2026-10-08 08:00:00",
  "endDate": "2026-10-11 08:00:00"
}
```

客户端小时窗口约为 3 天（`259200000` 毫秒）。`data`：`HourBloodLineBean[]`，比趋势点多一个 `time`。

点选趋势柱后查状态：`POST /bpmeterapp/api/device/trend/data/status`

```json
{
  "devSn": "",
  "devMeasurer": "1",
  "dimension": "day",
  "measuredTime": "2026-10-11 08",
  "recordKey": "",
  "source": ""
}
```

时间截断规则：

- `day`：`measuredTime` 取到小时，`substring(0, 13)`，即 `yyyy-MM-dd HH`
- `week`：取到日，`substring(0, 10)`
- `month`：同样按界面选中的日期传入

时段统计：`POST /bpmeterapp/api/device/time/period/data`

```json
{
  "devSn": "",
  "devMeasurer": "1",
  "dimension": "hour",
  "beginDate": "2026-10-11 08:00:00",
  "endDate": "2026-10-11 09:00:00"
}
```

周、月调用时 `dimension` 经常不传，只传 `beginDate` / `endDate`（`yyyy-MM-dd`）。  
`data`：`TimePeriodDataBean`，字段为 `highAvg`、`lowAvg`、`heartRateAvg`、`measuredCount`、`measuredStatus`、`status`、`rowKey`、`source`。

概览：`POST /bpmeterapp/api/device/overview/data`

```json
{
  "devSn": "",
  "devMeasurer": "1",
  "measuredTime": ""
}
```

`data`：`highAvg/highMax/highMin`、`lowAvg/lowMax/lowMin`、`heartRateAvg/heartRateMax/heartRateMin`。

有测量记录的日期：`POST /bpmeterapp/api/device/calendar/data`

```json
{ "devSn": "", "devMeasurer": "1" }
```

`data`：`[{ "measuredTime": "" }]`。

## 5. 测量数据上传

设备通过蓝牙把十六进制包交给 App，App 再上传云端。只做远程读取时可以跳过本节。

`POST /bpmeterbluetooth/api/send/dev/data`  
Header：`token`。

```json
{
  "devSn": "",
  "commandFlag": "81",
  "datas": ["<十六进制字符串>", "<十六进制字符串>"]
}
```

| commandFlag | 含义 | `datas` 处理 |
| --- | --- | --- |
| `81` | 测量结果包 | 原样上传，一次一条 |
| `FB` | 波形/过程包 B | 原样 |
| `FC` | 波形/过程包 C | 去掉前 6 个十六进制字符再上传 |
| `FD` | 波形/过程包 D | 去掉前 6 个十六进制字符再上传 |

上传顺序：先 `FB`，成功后 `FC`，再 `FD`。同一 `taskId` 的包传完后删除本地队列，再刷新最近数据。

`data` 成功时客户端判断字符串等于 `"success"`。

本地队列字段（`PostBluetoothUploadDataBaseBean`）：`commandFlag`、`datas`、`devSn`、`taskId`、`receiveFinish`（`2` 表示该任务可上传）。

### 5.1 测量结果包（命令类型 0 或 1）

载荷是十六进制文本，按字符切片，不是按字节数组下标。数值字段用十六进制转十进制（`ConvetTo.toDecimal`）。

正常测量（`parseAPackgeData(0|1)`）字段顺序：

| 顺序 | 十六进制字符数 | 字段 | 解析 |
| --- | --- | --- | --- |
| 1 | 8 | measuredId | 转十进制 |
| 2 | 14 | measuredTime | 原文，形如 `yyyyMMddHHmmss` |
| 3 | 8 | measuredZero | 转十进制 |
| 4 | 8 | measuredZeroTwo | 转十进制 |
| 5 | 2 | networkSign | 转十进制 |
| 6 | 2 | measurer | 转十进制，对应云端测量人 |
| 7 | 8 | cuffParam | 转十进制，袖带参数 |
| 8 | 12 | 柯氏音 | 每 4 字符一组：收缩压、舒张压、脉搏 |
| 9 | 12 | 示波法 | 同样三组 |
| 10 | 4 | normalMeasuredEx | 转十进制；末位为 `1` 表示心律不齐 |
| 11 | 2 | measuredModel | 转十进制 |

`measuredType == 0` 时采用示波法血压计算分级；`measuredType == 1` 时采用柯氏音。

异常测量（类型 2）在袖带参数后是 2 字符异常码，然后是测量模式，没有血压三元组。

类型 4 / 100 是采样率与压力斜率等波形参数，云端读取接口不直接返回这组原始值。

校验：对去掉末尾 4 字符后的每个十六进制字符做数值累加，格式化为 4 位大写十六进制，与末尾 4 字符比较。

## 6. 血压分级

设备解析（`DataParsing.getBloodPressureStatus`，单位 mmHg）把收缩压、舒张压映射为 `status`：

| status | 条件 | 文案 |
| --- | --- | --- |
| `3` | 收缩压 ≥ 180 或舒张压 ≥ 110 | 三级 |
| `2` | 收缩压 160–179 或舒张压 100–109 | 二级 |
| `1` | 收缩压 140–159 或舒张压 90–99 | 一级 |
| `9` | 收缩压 < 90 或舒张压 < 60 | 偏低 |
| `11` | 收缩压 120–139 或舒张压 80–89 | 正常高值 |
| `10` | 收缩压 < 120 且舒张压 < 80 | 正常 |
| `-1` | 未命中 | 界面当正常显示 |

首页图表使用了另一套简化规则，只区分三档：

| status | 条件 |
| --- | --- |
| `9` | 收缩压 < 90 或舒张压 < 60 |
| `11` | 收缩压 ≥ 135 或舒张压 ≥ 85 |
| `10` | 其余 |

云端 `status` 建议按设备解析那套理解。界面文案函数 `getMStatusByStatus` 只覆盖 `1/2/3/9/10/11`。

## 8. 天地网关签名

仅当 Base URL 切到 `https://tiandi.hanvon.com/gateway/` 时使用。血压接口不使用这套头。

| `time-stamp` | 当前毫秒时间戳字符串 |
| `userId` | 登录用户 `id` |
| `sign` | 见下 |

```text
sign = MD5(
  "access-key=s74ahOolTOBhNZN5Z598"
  + "&method=" + HTTP方法
  + "&time-stamp=" + 毫秒时间戳
  + "&url=" + 路径
  + "&secret-key=lcyYVKw7Hc3NdD2cBxJmZOZH0F0zqshAwQxnjSM0"

```

示例路径：`/model/gpt/history/pageWithEvent`。`method` 为 `POST` 或 `GET`。

## 9. 给 MCP 的最小接口面

若目标只是随时查看远程血压，封装这 6 个调用就够：

1. `member/verify/code/new/login` 或 `member/account/pwd/login` → 保存 `token`
2. `device/bind/list` → `devSn`
3. `measurer/list` → `devMeasurer`
4. `v3/device/latest/data/list` → 最近一次收缩压、舒张压、脉搏、时间、分级
5. `device/data/list` → 历史
6. `device/detail/data` 与 `device/trend/datas` → 详情和曲线

所有请求都带 `token` 头，Body 为 JSON，Base URL 为 `https://bpm.hanvon.com/`。
